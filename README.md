# PaintGuide

Веб-приложение — информационная база руководств по окраске моделей военной техники.
Пошаговые инструкции для разных уровней сложности, справочник красок с соответствиями
между брендами, личный кабинет и админ-панель.

Референс дизайна: Warhammer Colour и Warhammer Academy.
Референс функционала: ТЗ «Веб-приложение — информационная база руководств по технологии окраски моделей военной техники».

## Быстрый старт

```bash
# 1. Создать виртуальное окружение
python -m venv .venv

# 2. Активировать (Windows)
.venv\Scripts\activate
#    (Linux / macOS)
source .venv/bin/activate

# 3. Установить зависимости
pip install -r requirements.txt

# 4. Создать базу и загрузить демо-данные
python run.py init-db
python run.py seed --reset

# 5. Запустить
python run.py
```

Приложение откроется на **http://127.0.0.1:5000**

## Возможности

### Роли

| Роль | Возможности |
|------|-------------|
| **Гость** | Просмотр каталога, поиск, фильтры, справочник красок |
| **Пользователь** | + избранное (гайды и краски), вишлист, инвентарь красок, профиль |
| **Администратор** | + справочники, руководства и шаги, краски, пользователи, логи действий, статистика посещаемости |

### Аккаунты и подтверждение почты

* **Регистрация** создаёт аккаунт и отправляет письмо со ссылкой для
  подтверждения адреса. Пока адрес не подтверждён, **войти нельзя**.
* Все токены **одноразовые**, хранятся в базе только в виде хеша и
  имеют срок действия (двое суток для подтверждения, два часа для
  смены пароля).
* **Восстановление пароля** — по ссылке из письма; ответ одинаков
  для существующего и несуществующего адреса, чтобы по перебору нельзя
  было выяснить, кто зарегистрирован.
* **Смена адреса** требует подтверждения по новому адресу; старый при
  этом продолжает работать.
* **Удаление аккаунта** — по паролю, вместе с избранным, вишлистом и
  инвентарём.
* Вход, регистрация и восстановление пароля **ограничены по частоте**:
  перебор паролей и поток писем отсекаются.
* Почта отправляется через SMTP, если он задан переменными `MAIL_*`.
  Если SMTP не настроен, письма складываются в `instance/mail/*.txt` —
  ссылку из письма можно прочитать прямо оттуда.

#### Аккаунты переживают перезагрузку каталога

`flask seed --reset` очищает **только каталог**: гайды, краски и
справочники. Пользователи, их избранное, вишлист и инвентарь
остаются на месте — перезагрузка данных не должна сбрасывать учётные
записи. Удалить аккаунты можно только явно:

```bash
flask seed --reset-users
```

### Каталог руководств

* Полнотекстовый поиск по названию, описанию, стране и типу техники.
* Поиск идёт и по **техникам окраски** («проливка», «тонировка», «сухое крашение»),
  и по **краскам** — по названию и по коду (`AK11008`).
* Регистр не важен: поиск «проливка» находит те же гайды, что и «Проливка».
* Фильтры: **страна**, **тип техники**, **год выпуска**, **уровень сложности**.
* Сортировка: по дате, популярности, сложности, алфавиту.
* Постраничная навигация (24 гайда на страницу).

### Карточка руководства

* Обложка, страна, тип техники, **годы выпуска**, производство, экипаж.
* **Четыре уровня сложности** на каждый гайд — от «лёгкой» до «экспертной»,
  всегда в этом порядке. Уровень «Сложная» и «Экспертная» отличаются
  набором техник: тон, кромки, сухое крашение и погодные эффекты.
  По умолчанию открывается самый простой уровень.
* **Палитра модели**: свотчи крас; при наведении показывается, куда наносить краску и на каком шаге.
* **Пошаговые этапы**: краска + область нанесения + практический совет.
  Этап — это одна техника окраски, как в Warhammer Colour.
* Кнопка «Добавить все краски в вишлист».

### Справочник красок

* **3009 красок** девяти популярных брендов: Tamiya, Vallejo, AK Interactive, Humbrol, Mr. Color, Scale75, Lifecolor, Pacific88 и другие.
* Для каждой краски: бренд, линейка, **код**, название, тип, тон, HEX-образец и описание.
  Образец и описание восстанавливаются по названию, если источник их не отдал.
* **143 соответствия между брендами** — близкие оттенки разных производителей.
* Фильтры: бренд, линейка, тип, **техника нанесения**, поиск; сортировка по бренду, тону и коду.
* Фильтр по технике показывает краски, которые применяются на шаге выбранной техники:
  на «Проливке» — смывочные, на «Тонировке» — базовые тона.
* Карточка краски показывает соответствия и гайды, где она используется.

### Личный кабинет

* **Избранное** — гайды и краски.
* **Вишлист** — модели, руководства, краски и идеи с заметками и количеством.
* **Инвентарь красок** — что стоит на полке, а что в списке покупок.
* Профиль: никнейм, почта, смена пароля, сводка по мастерской.

### Админ-панель

* Сводка: счётчики, график посещаемости за 14 дней, последние действия.
* CRUD руководств с **конструктором шагов**: для каждого уровня сложности — до 12 этапов,
  у каждого этапа — до трёх крас из справочника с областью нанесения и советом.
* CRUD справочников: страны, типы техники, уровни сложности, бренды, линейки.
  Записи, на которые ссылаются другие данные, удалить нельзя — защита от битых ссылок.
* CRUD красок + массовый импорт из JSON.
* Пользователи: роли, блокировка.
* **Журнал действий** и **статистика посещаемости**.

### Оформление и локализация

* **Тёмная** тема (по умолчанию, в духе Warhammer Colour) и **светлая** тема.
  Переключатель в шапке; выбор запоминается в cookie и localStorage.
* Адаптивная вёрстка: десктоп, планшет, телефон.
* **Двуязычность**: русский (основной) и английский. Переключатель в шапке.

## Публикация в интернет

### Основной способ: Vercel (бесплатно, навсегда)

Vercel выполняет Flask-приложение как одну функцию и раздаёт сайт по
адресу `https://<проект>.vercel.app`. Аккаунты, избранное и вишлист
работают полноценно, база живёт во внешнем Postgres и не пропадает.

Подготовлено всё необходимое: точка входа `main.py`, сборка `build.py`,
настройки `vercel.json`. Остаётся три шага — см. раздел
**«Как опубликовать на Vercel»** ниже.

Требования к хостингу, которые уже учтены в коде:

* таблицы базы создаются при первом запуске, данные подливает сборка;
* секретный ключ и внешняя база обязательны — без них приложение
  сообщает об этом при старте, а не молча показывает пустой сайт;
* пул соединений к Postgres ограничен: на Vercel одновременно живёт
  несколько экземпляров приложения, и каждый держит свой пул;
* подтверждение адреса при регистрации по умолчанию **выключено**:
  письма не всегда доходят, а человек без входа просто не сможет
  пользоваться сайтом. Включается переменной окружения.

### Запасной способ: туннель с этого компьютера

Если публиковать через Vercel не хочется, сайт можно открыть
по обычной ссылке с вашего компьютера:

```bash
# 1. Запустить приложение (в одном окне)
python run.py

# 2. Открыть туннель (в другом окне)
python scripts/tunnel.py
```

Через несколько секунд появится адрес вида
`https://xxxxxxxx.serveousercontent.com` — его и нужно открыть на любом
устройстве. Ссылка работает, пока запущены оба окна.

Текущий адрес всегда лежит в файле **`tunnel-url.txt`** в корне проекта —
если окно потерялось, достаточно его прочитать.

Либо одной командой — `scripts\start-with-tunnel.bat`: она поднимает и сервер,
и туннель, и печатает ссылку.

**Связь может оборваться** — поэтому `scripts/tunnel.py` работает как supervisor:
сам переподключается и печатает новую ссылку. Ссылка при этом меняется.

### Постоянный адрес у туннеля (одноразовая настройка)

Службы туннелей выдают случайный поддомен на каждое соединение. Чтобы адрес
не менялся, зарегистрируйте SSH-ключ — это 2 минуты и нужна бесплатная учётная
запись:

```bash
python scripts/setup-tunnel-key.py
```

Скрипт создаст ключ и напечатает публичную строку. Дальше:

1. Откройте <https://console.serveo.net/settings> и зарегистрируйтесь.

## Как опубликовать на Vercel

Полный порядок шагов. Всё делается в браузере, из кода ничего
запускать не нужно.

### 1. Завести базу в Neon (бесплатно, 5 минут)

1. Откройте <https://neon.tech> и зарегистрируйтесь (можно через GitHub).
2. Создайте проект: имя любое, регион — ближайший к вам.
3. Neon сразу даёт базу и строку подключения. Нажмите **Connect** и
   скопируйте строку вида
   `postgresql://user:password@ep-xxx.region.aws.neon.tech/neondb?sslmode=require`
   — это и есть `DATABASE_URL`.

База пустая — наполним её при сборке (шаг 4), руками ничего делать
не нужно.

### 2. Загрузить код в GitHub (10 минут)

1. Создайте репозиторий на <https://github.com/new> — лучше **приватный**
   (бесплатный тариф Vercel некоммерческий, а лишних глазе�� контента
   в публичном репозитории быть не должно).
2. Из папки проекта выполните:

   ```bash
   git init
   git add .
   git commit -m "PaintGuide"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/paintguide.git
   git push -u origin main
   ```

   Файл `.gitignore` уже настроен: локальная база, папка `instance`,
   собранная статика `public/` и `.env` в репозиторий не попадут.

### 3. Создать проект в Vercel (5 минут)

1. Откройте <https://vercel.com> и зарегистрируйтесь (тем же GitHub).
2. **Add New → Project**, выберите свой репозиторий, **Import**.
3. Vercel сам увидит `vercel.json` — настройки framework, сборки и
   точки входа подставлять не нужно.
4. Нажмите **Deploy**.

### 4. Задать переменные окружения (обязательно)

В проекте Vercel: **Settings → Environment Variables**. Нужны две
переменные (применить к Production и Preview):

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | строка подключения из Neon (шаг 1) |
| `SECRET_KEY` | случайная строка, см. ниже |

Сгенерировать секретный ключ:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

**Почему секрет обязателен:** без него при каждом деплое меняются
подписи сессий — люди выходят из аккаунтов, а ссылки восстановления
пароля перестают работать. Приложение проверяет это при старте и
объясняет проблему вместо того, чтобы молча ломаться.

Остальные переменные уже заданы в `vercel.json`:
`FLASK_CONFIG=production`, `REQUIRE_DATABASE_URL=1`,
`EMAIL_VERIFICATION_REQUIRED=0`.

После сохранения переменных нажмите **Redeploy** — сборка поднимет
таблицы и залитёт 297 гайдов и 3009 красок в базу Neon.

### 5. Проверить

Откройте `https://<проект>.vercel.app`:

- главная, каталог, страница гайда, справочник красок — открываются;
- **Зарегистрируйтесь** и войдите: аккаунт должен сохраниться после
  перезагрузки страницы и после следующего деплоя;
- добавьте гайд в избранное и убедитесь, что он остался после
  обновления страницы.

### Если хочется свой домен

**Settings → Domains → Add**: добавьте домен, который уже куплен, и
создайте запись CNAME на адрес, который покажет Vercel. Домен на
бесплатном тарифе можно не покупать — адрес `vercel.app` работает.

### Если что-то пошло не так

* **Сайт пустой, а в логах нет ошибок** — не залилась база: проверьте
  `DATABASE_URL` и посмотрите логи сборки (на Vercel: **Deployments →
  Build Logs**).
* **«Для этого хостинга нужна внешняя база»** — не задан `DATABASE_URL`.
* **«Задайте постоянный SECRET_KEY»** — не задан `SECRET_KEY`.
* **Ошибка при сборке `pip install`** — в `requirements.txt` есть
  `psycopg[binary]`; если сборка идёт на Alpine, нужен `psycopg[c-binary]`.
* **Холодный старт** — первый запрос после простоя будит функцию
  (доли секунды на Vercel).
* **Финальная проверка перед деплоем** — локально:

  ```bash
  pip install -r requirements.txt
  python build.py          # соберёт статику в public/
  python run.py            # сайт на http://127.0.0.1:5000
  ```

## Технологии

| Слой | Технология |
|------|------------|
| Сервер | Flask 3.1, Jinja2 |
| ORM и БД | Flask-SQLAlchemy 3.1, SQLite (по умолчанию) / PostgreSQL (через `DATABASE_URL`) |
| Авторизация | Flask-Login, хеширование паролей Werkzeug (scrypt) |
| Формы и CSRF | Flask-WTF |
| Фронтенд | ванильный CSS (CSS Custom Properties) и JavaScript, без сборки |
| Локализация | собственный словарь `i18n/{ru,en}.json` |

Внешние сервисы **не требуются** — приложение полностью работает офлайн.

### Технические решения

* **Справочники не подмешиваются в глобальный контекст.** Каждый шаблон получает
  только те списки, которые ему нужны, — это экономит четыре запроса к базе
  на каждый просмотр страницы.
* **Список красок в конструкторе шагов отдаётся одним JSON-блоком** и разворачивается
  в выпадающие списки на клиенте (`static/js/admin.js`). Если рисовать все 225 красок
  в каждом из ~150 селектов, страница редактора весит 5.6 МБ; сейчас — 230 КБ.
* **Пагинация на всех списках** — каталог (24 на страницу) и справочник красок (40).
* **SQLite в режиме WAL + индексы** по стране, типу техники, году, сложности и коду краски.

## Переменные окружения

Скопируйте `.env.example` в `.env` и при необходимости измените значения.

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `SECRET_KEY` | случайный при старте | Ключ подписи сессий (задайте постоянный в продакшене) |
| `DATABASE_URL` | `sqlite:///instance/paintguide.db` | Подключение к PostgreSQL |
| `ADMIN_EMAIL` | `admin@paintguide.local` | Почта, приравниваемая к администратору |
| `DEFAULT_LOCALE` | `ru` | Язык по умолчанию |
| `SESSION_COOKIE_SECURE` | `false` | `true` для HTTPS |
| `FLASK_CONFIG` | `development` | `development` / `production` / `testing` |
| `PORT` | `5000` | Порт запуска |
| `MAIL_SERVER` | — | SMTP-сервер для писем с подтверждением и восстановлением пароля |
| `MAIL_PORT` | `587` | Порт SMTP |
| `MAIL_USERNAME` | — | Логин SMTP |
| `MAIL_PASSWORD` | — | Пароль SMTP |
| `MAIL_USE_TLS` | `true` | Шифрование STARTTLS |

Старые письма убираются автоматически, остаются последние пятьдесят:

```bash
python scripts/prune_mail.py
```

## Команды

```bash
python run.py                      # запустить сервер
python run.py init-db              # создать схему базы
python run.py seed                 # загрузить демо-данные (не перезаписывая)
python run.py seed --reset         # очистить базу и загрузить заново
python run.py create-admin EMAIL --password "пароль"
python -m pytest tests -q          # тесты

# Служебные скрипты (нужны один раз, требуют интернета)
python scripts/fetch_paints.py     # обновить каталог красок
python scripts/resolve_paints.py   # сверить ручные названия с каталогом
python scripts/fetch_covers.py     # подобрать обложки для руководств
```

### Проверка обложек

`scripts/fetch_covers.py` собирает галерею `docs/covers-report.html` —
сетку всех обложек с подписями. Откройте её в браузере: сплошная рамка —
фото найдено, пунктирная — машина осталась без снимка, ссылка ведёт на
категорию Commons для ручного выбора.

### Как поправить конкретную обложку

```bash
python scripts/fetch_covers.py t-34-85 --force
```

Скрипт переберёт источники заново. Если нужен конкретный файл — укажите его
название в `paintguide/seed/covers.json` в поле `title` и запустите сид.

Машины, для которых в Commons нет подходящей категории, ищутся по статье
Википедии: в `paintguide/seed/covers.py` есть словарь `WIKIPEDIA_ARTICLES`,
где слаг гайда сопоставлен со статьёй (`"kv-202": ("en.wikipedia.org", "T-10 tank")`).
Название статьи часто отличается от привычного: KV-202 известна как
«T-10 tank», а Type 4 Ke-Ni — как «Type 4 Ke-Nu light tank».

Скрипт делает несколько кругов по машинам, которые не нашлись сразу:
лимиты Commons строгие, и отказ приходится пережидать.

### Фоновые задачи

Долгие скрипты (сбор обложек, проверка) запускаются через помощник:
процесс идёт **без окна консоли**, номер его записывается в
`instance/background-jobs.json`, и остановить можно только именно его.

```bash
python scripts/background.py start .venv\Scripts\python.exe -u scripts/resolve_plan.py
python scripts/background.py list
python scripts/background.py stop resolve_plan
```

Журнал каждого задания — в `instance/logs/`.

### Проверка сайта

```bash
python scripts/audit.py
```

Скрипт проверяет обложки (все ли гайды закрыты, все ли файлы на месте),
согласованность базы, время ответа основных страниц и внутренние ссылки.
Отчёт складывается в `docs/audit-report.md`.

## Замечания по данным

* HEX-значения красок — ориентировочные, взяты по финишным карточкам производителей.
  Перед защитой рекомендуется сверить их с актуальными каталогами: на экране цвет
  всегда зависит от настройки монитора.
* Коды красок соответствуют публичной нумерации производителей.
* Видео в проекте нет: страницы содержат только текст, фотографии и справочные данные.
